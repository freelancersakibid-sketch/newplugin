# Known limitations and release gate

**This release candidate is not the full production-ready system requested.** See `AUDIT.md` for every open finding and feature.

- Report mutations require InnoDB and the standard WooCommerce product/postmeta datastore. Sites with custom product storage, DB routing/read replicas, hooks that commit transactions, or nontransactional tables require adaptation and testing. Existing engines are not automatically converted.
- Third-party stock writes, WooCommerce order stock writes and arbitrary SQL outside this command service do not receive this plugin's receipt/rollback guarantees. A row lock serializes conflicting database writes; it cannot make a third-party physical return or an external API call idempotent.
- The tracker only deduplicates repeated identical item callbacks within one request. Courier plugins must be coordinated through a durable return-event adapter before claiming cross-request duplicate-restoration prevention. Current matching of custom return statuses remains heuristic.
- Request receipts currently scope commands by physical owner. A change to product stock ownership between an uncertain command and its retry requires manual reconciliation; this phase has no immutable batch owner-map manifest.
- On bulk failure, successful owners remain committed. Retrying exactly the same command and ID replays those owners. Changing selected rows or the payload is a new operation. Pending browser IDs are retained only when browser session storage is available. Receipts are retained indefinitely; there is no cleanup job. Do not delete them without an explicit retention/idempotency policy.
- Legacy audit dates are stored in site-local time. The report retains a current-offset SQL conversion for those dates, so historical daylight-saving changes can affect comparison to GMT order dates. A UTC timestamp migration/backfill and timezone tests remain necessary before closing finding 7.
- New historical records are evidence only. Original records are preserved; original `historical_import` sales are displayed/filtered as unverified without rewriting the database. Unknown stock ownership in legacy rows is not inferred. Partially restocked order evidence has no dedicated fixture in this phase.
- Historical scans capture a maximum order ID and inspect completion status when that ID is visited. A later status change behind the cursor requires a fresh scan. The browser must stay active for batching; no Action Scheduler import/export recovery exists.
- Audit paging is insertion-ID order. Its high watermark prevents new insertions shifting pages, but existing rows may still be reclassified by an integration between requests. Inventory page numbers are live offsets and may shift under concurrent catalog changes.
- Inventory CSV holds a database snapshot for the whole synchronous export and writes a temporary disk file. Very large exports can hit request timeout or disk limits and hold an old read view; no resumable export is promised. Source tables must be InnoDB for the advertised snapshot behavior.
- Historical order/postmeta aggregations remain expensive. No 10,000-product, 50,000-variation or hundred-thousand-audit benchmark has been run. No compact metrics, candidate-ID pipeline, cross-request summary cache or bulk thumbnail metadata prefetch exists yet. Existing per-request summary caching is retained and invalidated on audit writes.
- Shared retail values repeat on variation rows. Summary deduplicates the physical owner; users must not sum repeated variation pool values. Retail value is not actual product cost. No cost fields or cost-access feature is added.
- Forecasts cover a fixed 30-day demand horizon. They do not account for lead time, safety stock, reserved stock, incoming POs, returns or seasonality. Sales remain gross completed-order quantities, not net/refund-adjusted accounting sales.
- Only `manage_woocommerce` currently controls access. Read-only staff, PO/cost capabilities and saved views are not implemented.
- PHP 7.4/WordPress 6.2/WooCommerce 7.6 declarations are inherited minimums; that matrix has not been tested. Automated tests used PHP 8.3.36, WordPress 7.1.4, WooCommerce 11.2.2 and MariaDB 11.4 only. MySQL, persistent Redis/Memcached caches, multisite/network activation, HPOS synchronization under concurrent activity, external courier integrations and real store data remain unqualified.
- No mail transport is configured in the test environment. Test-order mail is intercepted; no email-delivery claim is made.

Production release requires closing the open audit findings, implementing the remaining requested workflows and running the compatibility, integration, recovery, load and security scenarios listed in the request.
